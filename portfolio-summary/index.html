Case study 1 of 3 · Shipped

Omnione Design System

My role

Senior Product Designer and Design Manager

Scope

Audit, tokens, component library, adoption in code

Year

2024

Four product teams at OmniRetail were each drifting on their own: the same primary button looked different in Omnibiz, OmniHub, OmniOne and Omnipay. I audited the existing patterns, defined a two-tier token structure, built the component library in Figma, and worked with engineering to adopt it in code, so one shared language reached all four without slowing any of them down.

  • 60+components built and documented in the shared library
  • 2,300+variants across states, sizes and product-specific needs
  • 2-tierfoundation tokens feeding semantic, usage-level tokens

Fundall: Salary Advance on mobile

My role

Lead product design, mobile loans and salary advance

Scope

Flow redesign, visibility on mobile, trust and repayment clarity

Case study 3 of 3 · Independent concept

Nsimbi: Chat-first payments

My role

Research, interaction design, design system, prototype in code

Scope

Four design touches on one payment journey, localised for Nigeria

Status

Independent concept, not commissioned

Nsimbi is a mobile money app by Felix Kitaka, where you ask for airtime or data in one chat message and approve each purchase. The idea already worked. I looked at what stands between a person and a confident tap on Buy, and added four touches that make each payment easier to read, check and correct. I built the prototype in code and redesigned it for people paying in naira.

  • 4design touches on one payment journey: review, approval, the queue and recovery
  • ₦localised throughout: money, banks, numbers and verification, not only the currency symbol
  • 7simulated test runs, reported as predicted evidence, not production results
Simulated accounts and payments. Full case study: muidemakz.com/nsimbi-three-purchases.html
