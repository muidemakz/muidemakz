# Output: code or artifact

Read when the selected target is working code or an artifact. Shared rules for all targets are in [output targets](output-targets.md).

Use the user's existing framework and conventions when available. If the implementation environment is unspecified and affects the deliverable, resolve it as an assumption before building. Do not introduce a UI framework merely because another skill uses it.

1. Read the project-scoped context record for an existing product, then reconcile it with the current codebase. **Before designing any screen or element**, inspect the codebase's component library, including components, variants, icon components, and illustration assets. Reuse what fits, including in scoped edits. Show any gap and obtain approval through the choice layer before building a reusable component or proper variant. Never restyle an existing component to fake a variant.
2. Represent the validated primitives and semantic aliases in the environment's native token mechanism, such as CSS variables or a theme object. Components consume semantic roles; keep raw values in the primitive definitions.
3. Build the agreed interface from fitting existing components and any approved new atoms, molecules, or organisms. Use fluid widths and responsive layout rules; define breakpoints where content order, navigation, or component behavior changes. Every content-bearing element must have an intermediate-width rule: text and labels wrap, icon-label pairs reflow, typography and icons use approved size steps, content grows with intrinsic height, metadata and controls stack or reflow, and actions remain reachable. Verify that content remains readable instead of shrinking below minimums, clipping, or truncating to avoid overflow. Use fluid width plus max-width for readable content, headers, forms, grids, previews, and dialogs when a wider frame would otherwise create excessive line length or weak composition; document full-bleed exceptions. Implement the applicable component states from [component states](component-states.md), including focus, hover, pressed, selected, disabled, loading, success/error, disclosure, and recovery behavior. Use semantic state styles and reusable variants, not one-off overrides. Exercise the transitions in the rendered artifact. Use the brand's icon components and illustration assets. If no set or style exists, use only the approved choice documented in [component library](component-library.md). Keep icon styling and illustration styling consistent, store them in the component library, and mark illustration placeholders. Preserve unrelated code and existing valid conventions in an edit. Use real assets and planned functional copy; label placeholders and simulated behavior.
4. For a prototype, make the agreed interactions and states work within the chosen environment. Do not present mocked transactions or fabricated product data as live capabilities.
5. Inspect the rendered result at narrow, just-before and just-after-breakpoint, intermediate, and wide target sizes and exercise the affected flow. Resize through intermediate widths; confirm every content-bearing element wraps or recomposes, uses intrinsic height, has no clipping, overlap, accidental truncation, unreadable type, or horizontal overflow, and keeps labels, icons, controls, and touch targets reachable. Exercise applicable state transitions, including keyboard/focus, hover or pointer, pressed, selected, disabled, loading, success/error, disclosure, and recovery behavior. Check relevant accessibility behavior, including keyboard/focus, labels, error states, and contrast. Run applicable existing project checks. A successful build alone does not prove visual fidelity or accessibility.
6. Deliver the runnable artifact or exact file locations with launch instructions when needed. Identify token definitions, reused components, approved new components and variants, icon components, illustration assets, performed checks, and remaining limitations. Mark each approved new component or variant as new. If execution or visual inspection is unavailable, state that clearly.
